Trace - AI 日记应用

打开产品demo

Trace是一款基于正向心理学的AI日记应用，将用户的日常记录转化为持续的自我认知系统，帮助用户实现自我成长与情绪疗愈。

（1）产品背景

产品痛点

情绪管理是高频、真实却常被忽视的日常需求。在高压环境下（留学、申请季、季节性抑郁高发期），用户往往会经历情绪低谷——但单靠意志力硬扛是不可持续的，用户需要一个可以长期依赖的外部调节工具。

具体痛点包括：

  • 情绪低谷时难以客观看待自身状态，容易陷入负面循环，无法主动识别支撑自己的积极资源。
  • 每次低谷都在从零开始，缺少可复用的情绪复原路径。
  • 记录了情绪，但没有机制帮助用户回望和巩固积极体验，导致正向记忆容易被遗忘。
  • 情绪起伏大时，很难单靠回忆客观评估「这段时间自己其实做到了什么」。

产品目标

Trace 的目标不是帮用户「解决」情绪问题，而是提供一套可持续的自我调节系统：

  • 通过 3-2-1 结构化框架，降低每日记录的门槛，同时提升输入的信息质量。
  • 通过 AI 跨时间分析，帮助用户从积累的记录中提取情绪规律、思维模式与隐藏的积极信号。
  • 通过回看机制（Lottery Box、AI Analyzer），将过去的积极体验持续强化，形成稳定的心理记忆系统。
  • 帮助用户从「情绪的被动承受者」逐渐成为「自我成长的主动观察者」。

（2）目标用户

用户画像

  • 学生或职场早期用户，希望以低门槛、低压力的方式坚持自我反思——记录是日常习惯，而不是需要完成的写作任务。
  • 对个人隐私敏感，倾向单人使用，数据不对外共享。
  • 习惯简短的中文输入，愿意偶尔借助 AI 获得情绪洞察与积极反馈。

使用场景

  • 睡前 5–10 分钟：在日记 Tab 填满三项区块，亦可一键生成当日配图。
  • 周末复盘：在日历 Tab 把多日内容写入「存档」，勾选日期区间做情绪趋势或隐藏积极信号分析。
  • 情绪低落时：翻到 AI Tab 继续追问，或对某段分析结果进行二次对话。

（3）核心功能

写日记

（1）结构化日记书写

  • 描述：将一日记录拆成可折叠的三段：3 件感恩的事情、2 个可以改进的空间、1 句自我肯定。
  • 实现方式：纯前端表单、区块折叠与标题快捷操作；草稿与按日存档写入 localStorage；输入区附带装饰性太阳动画。
  • 操作流程：写日记 Tab → 展开各区块 → 填写 → 「保存到日历」→ 生成今日 AI 插图或切换到其它 Tab。

（2）今日 AI 插图（感恩 → 意象图）

  • 描述：从已填日记的条目中抽样一条作为提示，生成一张插画，强化「今日痕迹」的体验。
  • 实现方式：用户点击生成按钮后，前端向服务端发送请求；服务端调用 Google Gemini 图像模型生成图片，并返回可直接展示的图片链接；前端拿到链接后显示图片，同时激活下载选择。
  • 操作流程：至少填写一条感恩 → 点击生成 → 等待态展示 → 出图。

日历

（1）日历存档

  • 描述：按月份格子查看哪些天有存档的日记内容，可从格子进入单日日记摘要或每日插图。
  • 实现方式：月历 DOM + 存档 JSON；部分演示日用预设图片映射；支持与日记表单之间的读写同步。
  • 操作流程：日历 Tab → 点击分析，选择分析 → 点选日期 → 查看分析。

（2）每日刮刮乐

  • 描述：在日历视图中刮开刮刮乐 UI 的图层，显示一句由随机日记内容提炼的短句，可溯源到原始日记条目。
  • 实现方式：Canvas 刮层 + POST /api/scratch-summary（Gemini 文本）；溯源弹窗展示对应日记片段。
  • 操作流程：在刮刮区域滑动 → 露出文案 → 可选「查看日记源」跳转模态框。

（3）区间 AI 分析（情绪趋势 + 隐藏积极信号）

  • 描述：用户自选连续日期，可选两类分析：情绪得分曲线、从「改进 + 肯定」文本中提炼积极视角的长解读。
  • 实现方式：用户在向导式弹窗（Modal）里选择日期范围和分析类型，点击生成后，前端分别向 /api/emotion-trend 与 /api/hidden-positive-signals 发起 POST 请求。服务端接收请求后调用 LLM 进行分析：情绪趋势返回按日打分的序列（每天一个 1–10 的分数），隐藏积极信号返回一段长文本洞察。两个功能均优先调用 Claude（需配置 Anthropic API Key），未配置或调用失败时自动降级使用 Gemini。分析结果以会话卡片的形式写入 AI 聊天 Tab 展示。
  • 操作流程：打开分析 → 选日 → 勾选分析类型 → 运行 → 自动切到 AI 聊天 Tab 浏览图表或者文案。

AI 聊天

  • 描述：在分析结果之余，保留自由追问入口，与同一后端的会话式补全衔接。
  • 实现方式：POST /api/chat；当前服务端使用 Gemini 文本模型整段生成回复（需在环境变量中配置 GEMINI_API_KEY）。
  • 操作流程：切换到 AI Tab → 输入追问 → 等待整段回复展示（当前实现为非流式 JSON）。

（4）用户旅程

每张界面与正下方序号步骤对应；整体设计目标是从首次进入到完成一次「有意义的复盘」。左 → 右：日记｜日历｜AI 聊天。

  1. 打开 Demo（手机壳框架内的 Web 应用），默认落在日记 Tab。
  2. 展开三个主题块，按引导填写感恩 / 改进 / 肯定（可先写一部分再收起）。
  3. 可选：点击生成今日配图，确认 AI 返回值并保存视觉记忆。
  1. 将当日内容同步到日历存档，使月历上出现可点的记录日。
  2. 切换日历 Tab：浏览其它日期、点开刮刮卡或缩略内容。
  3. 在月历触发 AI 分析向导：框选区间 → 勾选「情绪趋势」和/或「隐藏积极信号」→ 发起请求。
  1. 自动进入 AI Tab：阅读趋势线卡片与解读卡片，按需继续文字对话。
  2. 带着具体句子或下一个行动设想离开产品（本产品不强制闭环任务系统）。

（5）界面设计

本节只写产品级视觉与信息架构原则；具体组件实现、状态与工程向取舍见下方时间轴「3. 前端设计」，避免两处逐条复述。

风格与配色

  • 整体：暖色弥散渐变 + 轻玻璃拟态的手机壳容器，情绪化但不过艳。
  • 三块日记：橙 / 薄荷绿 / 粉系点缀区分主题，条目前缀与勾选态一致。
  • 情绪趋势图：低分蓝 — 中段灰 — 高分橙分区，线段在跨区间时渐变过渡。

参考与布局

  • 参考：移动日记类产品的「单手可完成」信息流 + Headspace/Calm 类柔和梯度背景的思路（非一比一临摹）。
  • 布局：顶部 Tab（日记｜日历｜AI）切换整页视图；日历内次级模态承载选日与分析向导；日记主列垂直滚动。

（6）技术方案

前端

  • 页面构建：HTML + CSS + 原生 JS，无框架，便于作品集直接打开与部署。
  • 本地数据管理：使用 localStorage 存储日记草稿、按日存档、刮刮记录，与日历、分析弹窗联动。
  • 图形与动效 — SVG / Canvas 实现情绪曲线与刮刮涂层；太阳动画（sun-canvas.js）基于 Canvas 2D + requestAnimationFrame 逐帧渲染，输入框获焦触发。

后端

  • Node.js http 单文件服务：同源托管静态页 + REST 风格 JSON API；密钥与模型选择均在服务端完成，前端只消费 JSON。

  • AI 模型分配与备用机制：以下表按能力与接口列出所用模型及备用策略。

    能力 接口 优先 备用 / 说明
    AI 聊天（自由追问 · 会话补全） /api/chat Gemini（文本链） —
    写日记 · （2）今日 AI 插图（感恩 → 意象图） /api/generate-image Gemini 图像 —
    日历 · （2）每日刮刮乐 /api/scratch-summary Gemini（文本链） —
    日历 · （3）区间 AI 分析 — 情绪趋势 /api/emotion-trend Claude（Anthropic 模型链） 无 Key 或链式失败时用 Gemini；仅 Gemini Key 时直接 Gemini
    日历 · （3）区间 AI 分析 — 隐藏积极信号 /api/hidden-positive-signals Claude 流式 失败则 Gemini 伪流式；再失败则规则化文案

    表内「文本链」指多个 Gemini 文本模型顺序尝试。限流或瞬时失败时，文本类 Gemini 会先退避重试，再在链内换下一模型；这与「Claude → Gemini」的跨厂商 fallback 是不同层级的容错，可叠加生效。

第三方服务

  • Google Gemini：配图生成、日记 Tab 聊天 /api/chat、刮刮摘要；情绪单日打分与隐藏积极信号的兜底路径。
  • Anthropic Claude：情绪趋势单日打分与隐藏积极信号解读的优先路径（需 ANTHROPIC_API_KEY）。

上表已列全量 API 路径；前端对它们均为同源 POST、application/json，与静态页由同一 server.js 进程提供。

（7）MVP 范围

✅ 第一版包含

  • 结构化日记三项、折叠块、本地草稿与按日存档。
  • 月历浏览、演示日视觉、刮刮卡与溯源。
  • 区间分析（情绪趋势图 + 隐藏积极信号）与结果在 AI Tab 的卡片化展示。
  • AI 配图、AI 对话、基础错误提示与「需启动本地 server」说明。

❌ 第一版不包含

  • 账号注册登录、云端同步、多设备冲突解决。
  • 社交分享、协作、公开社区。
  • 复杂报表导出、订阅付费、推送提醒。
  • 医学级心理评估或危机干预流程（产品定位为自我反思工具，非医疗）。

（8）边界情况

边界场景 处理策略
无感恩即生图 前端拦截并提示先填写至少一条感恩内容。
区间内无存档或字段为空 分析接口返回明确 400 文案；隐藏积极信号在缺「改进/肯定」时提示无法分析。
API 失败 / 非 JSON / 网络错误 状态栏与弹窗说明；引导检查 node server.js、.env 与浏览器是否允许访问本地 API。
模型限流或 overload 服务端对 Gemini 带退避重试与模型链切换；隐藏积极信号可在模型全失败时使用规则化 fallback 文案。
情绪分数跨档 折线颜色在相邻点之间做渐变，避免硬切视觉断层。
localStorage 满或禁用 静默失败时已尽量 try/catch；产品级后续应显式降级提示。

3. 前端设计

（1）写日记

写日记页面是Trace的核心入口。用户每天在这里完成一次3-2-1记录——三件感恩的事、两个可以改进的地方、一句对自己的肯定。

页面采用折叠式输入模块，每个板块归属于对应的标题下。输入框获焦时，太阳动画随之出现，为书写营造温暖的仪式感。

完成记录后，AI根据当天内容生成一张专属插画，为这天留下印记。

（2）日历

页面由两个模块构成。上方为月视图日历，每天完成日记后当日格子显示AI生成的插画缩略图，点击可查看当天完整的3-2-1记录。

下方为刮刮乐模块，系统将用户所有历史日记中的Gratitude条目汇总为文本库，调用LLM进行语义整合，输出一句提炼后的正向表达藏于涂层之下。刮开即可看见来自过去的一段正向记忆。
