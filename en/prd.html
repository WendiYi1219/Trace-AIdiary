Trace - AI Diary App

Trace is an AI diary app grounded in Positive Psychology. It turns daily reflection into a continuous self-awareness system, supporting personal growth and emotional repair.

(1)Background

Pain Points

Emotional regulation is a frequent, real, yet often overlooked daily need. Under high-pressure conditions (studying abroad, application season, seasonal depression peaks), users often hit emotional lows—and white-knuckling through them with willpower alone isn't sustainable. Users need a long-term external regulation tool they can rely on.

Specific pain points include:

  • It's hard to view yourself objectively during emotional lows; you fall into negative loops, unable to actively recognize the positive resources sustaining you.
  • Every low feels like starting from zero, with no reusable recovery path.
  • Emotions get recorded, but there's no mechanism to revisit and reinforce positive experiences—so positive memories fade easily.
  • When emotions fluctuate, it's hard to objectively assess "what you actually accomplished during this period" from memory alone.

Product Goals

Trace's goal isn't to "solve" users' emotional problems—it's to provide a sustainable self-regulation system:

  • Use a 3-2-1 Structured Framework to lower the daily entry threshold while raising input quality.
  • Use AI Cross-Temporal Analysis to surface emotional patterns, thought habits, and hidden positive signals from accumulated entries.
  • Use Lookback Mechanisms (Lottery Box, AI Analyzer) to continuously reinforce past positive experiences and build a stable psychological memory system.
  • Help users gradually shift from "passive recipient of emotions" to "active observer of their own growth."

(2)Target Users

User Personas

  • Students or early-career users who want low-friction, low-pressure self-reflection—where journaling is a daily habit, not a writing assignment to complete.
  • Privacy-sensitive, prefer single-user mode, no data sharing.
  • Used to short-form input, occasionally welcoming AI-generated emotional insights and positive feedback.

Use Cases

  • Pre-sleep 5–10 minutes: fill in the three sections in the Diary tab, optionally generate today's image with one tap.
  • Weekend reflection: in the Calendar tab, archive multiple days, select a date range to run Emotion Trend or Hidden Positive Signals analysis.
  • During emotional lows: switch to the AI tab to ask follow-up questions or have a second-round conversation about an analysis.

(3)Core Features

Diary

(1)Structured Journaling

  • Description: Splits a day's entry into three foldable sections: 3 things to be grateful for, 2 areas for improvement, 1 self-affirmation.
  • Implementation: Pure frontend form with foldable sections and header shortcuts; drafts and per-day archives stored in localStorage; decorative sun animation in the input area.
  • Flow: Diary tab → expand sections → fill in → "Save to Calendar" → generate today's AI illustration or switch tabs.

(2)Daily AI Illustration (Gratitude → Imagery)

  • Description: Samples one entry from the filled diary as a prompt to generate an illustration, reinforcing the experience of "today's trace."
  • Implementation: User clicks generate; frontend sends a request to the server; server calls Google Gemini's image model and returns a displayable image URL; frontend renders the image and enables download options.
  • Flow: Fill at least one gratitude entry → click generate → loading state → image returns.

Calendar

(1)Calendar Archive

  • Description: View which days have archived diary content via a monthly grid; click a cell to enter the daily summary or daily illustration.
  • Implementation: Monthly calendar DOM + archive JSON; some demo days mapped to preset images; supports read/write sync with the diary form.
  • Flow: Calendar tab → click Analyze → choose analysis type → select dates → view results.

(2)Daily Scratch Card

  • Description: In Calendar view, scratch off the UI overlay to reveal a short sentence distilled from a random diary entry, traceable back to the source.
  • Implementation: Canvas scratch layer + POST /api/scratch-summary (Gemini text); a source modal shows the corresponding diary fragment.
  • Flow: Swipe to scratch → reveal copy → optional "View Diary Source" opens modal.

(3)Range AI Analysis (Emotion Trend + Hidden Positive Signals)

  • Description: User selects a continuous date range and chooses between two analyses: an emotion score curve, or a long-form positive interpretation extracted from the "Improvement + Affirmation" text.
  • Implementation: The user selects a date range and analysis type via a wizard modal. On submit, the frontend sends POST requests to /api/emotion-trend and /api/hidden-positive-signals respectively. The server calls LLMs: Emotion Trend returns a sequence of 1–10 daily scores; Hidden Positive Signals returns a long-form text insight. Both prefer Claude (requires Anthropic API Key); on failure or missing key, automatically falls back to Gemini. Results display as conversation cards in the AI Chat tab.
  • Flow: Open analysis → select dates → check analysis types → run → auto-switch to AI Chat tab to view chart or text.

AI Chat

  • Description: Beyond analysis results, preserves a free follow-up entry connected to the same backend's conversational completion.
  • Implementation: POST /api/chat; the current server uses a Gemini text model for full-message generation (requires GEMINI_API_KEY in env).
  • Flow: Switch to AI tab → input question → wait for full reply (current implementation is non-streaming JSON).

(4)User Journey

Each interface corresponds to the numbered steps below; the overall design goal is to go from first entry to a meaningful reflection in one session. Left → right: Diary | Calendar | AI Chat.

  1. Open the demo (web app inside a phone-shell frame); lands on the Diary tab by default.
  2. Expand the three theme blocks; fill in Gratitude / Improvement / Affirmation per the prompts (can fill partially, then collapse).
  3. Optional: click to generate today's image, confirm the AI return value, save the visual memory.
  1. Sync today's content to the calendar archive so a clickable record day appears.
  2. Switch to the Calendar tab: browse other dates, open scratch cards or thumbnail previews.
  3. Trigger the AI analysis wizard from the calendar: select a range → check "Emotion Trend" and/or "Hidden Positive Signals" → submit.
  1. Auto-lands on the AI tab: read the trend chart card and interpretation card, continue the conversation as needed.
  2. Leave the product carrying a specific sentence or a next-action thought (the product doesn't enforce a closed-loop task system).

(5)Interface Design

This section only covers product-level visual and information architecture principles. Specific component implementation, states, and engineering trade-offs are in the timeline section "3. Frontend Design" below to avoid repetition.

Style & Color

  • Overall: warm diffuse gradient + light glassmorphism phone-shell container, emotional but not over-saturated.
  • Three diary blocks: orange / mint / pink palettes mark each theme; entry prefixes and check states stay consistent.
  • Emotion trend chart: low-score blue — mid gray — high-score orange zones; line gradient interpolates across zone transitions.

Reference & Layout

  • Reference: mobile journaling apps with a single-handed information flow + soft gradient backgrounds inspired by Headspace / Calm (not 1:1 copies).
  • Layout: top tabs (Diary | Calendar | AI) switch the full-page view; the calendar's secondary modal carries date selection and analysis wizard; the diary main column scrolls vertically.

(6)Technical Approach

Frontend

  • Page construction: HTML + CSS + vanilla JS, no framework, so the case study runs by simply opening the file.
  • Local data management: uses localStorage to store diary drafts, per-day archives, and scratch records, syncing with the calendar and analysis modals.
  • Graphics & motion — SVG / Canvas implements emotion curves and scratch overlays; the sun animation (sun-canvas.js) uses Canvas 2D + requestAnimationFrame frame-by-frame rendering, triggered on input focus.

Backend

  • Node.js single-file http service: hosts static pages from the same origin + REST-style JSON API; key management and model selection happen on the server side; the frontend only consumes JSON.

  • AI Model Routing & Fallback Strategy: the table below lists models used and fallback strategies by capability and endpoint.

    Capability Endpoint Primary Fallback / Notes
    AI Chat (open follow-up · conversational completion) /api/chat Gemini (text chain) —
    Diary · (2) Daily AI Illustration (Gratitude → Imagery) /api/generate-image Gemini Image —
    Calendar · (2) Daily Scratch Card /api/scratch-summary Gemini (text chain) —
    Calendar · (3) Range AI Analysis — Emotion Trend /api/emotion-trend Claude (Anthropic model chain) Falls back to Gemini if no key or chain fails; uses Gemini directly when only Gemini key is configured
    Calendar · (3) Range AI Analysis — Hidden Positive Signals /api/hidden-positive-signals Claude streaming Falls back to Gemini pseudo-streaming on failure; falls back to rule-based copy on further failure

    "Text chain" means multiple Gemini text models tried in sequence. On rate limits or transient failures, Gemini text first applies backoff retry, then switches to the next model in the chain; this is a different layer of fault tolerance from the cross-vendor "Claude → Gemini" fallback, and they stack.

Third-Party Services

  • Google Gemini: image generation, Diary tab chat /api/chat, scratch summary; fallback path for daily emotion scoring and hidden positive signals.
  • Anthropic Claude: primary path for emotion trend daily scoring and hidden positive signals interpretation (requires ANTHROPIC_API_KEY).

The table above lists the full API surface; the frontend POSTs to all of them with application/json from the same origin, served by the same server.js process.

(7)MVP Scope

✅ V1 Includes

  • Three structured diary sections, foldable blocks, local drafts and per-day archives.
  • Monthly calendar browsing, demo-day visuals, scratch cards with sourcing.
  • Range analysis (Emotion Trend chart + Hidden Positive Signals) with results displayed as cards in the AI tab.
  • AI illustration, AI conversation, basic error prompts, and "requires local server" instructions.

❌ V1 Excludes

  • Account registration/login, cloud sync, multi-device conflict resolution.
  • Social sharing, collaboration, public community.
  • Complex report export, subscription payments, push notifications.
  • Medical-grade psychological assessment or crisis intervention (positioned as a self-reflection tool, not medical).

(8)Edge Cases

Edge Case Handling Strategy
Generate image without gratitude Frontend blocks with a prompt to fill at least one gratitude entry first.
No archive in range or empty fields Analysis API returns explicit 400 copy; Hidden Positive Signals shows "cannot analyze" when "Improvement / Affirmation" is missing.
API failure / non-JSON / network error Status bar and modal explain the issue; guides the user to check node server.js, .env, and whether the browser allows local API access.
Model rate limit or overload Server-side Gemini backoff retry and model chain switching; Hidden Positive Signals can use rule-based fallback copy when all models fail.
Emotion score zone crossing Line color gradient between adjacent points avoids hard visual cuts.
localStorage full or disabled Currently silently fails with try/catch; product-level next step is an explicit degradation prompt.

3. Frontend Design

(1)Diary

The Diary page is Trace's core entry — a daily 3-2-1 record: three gratitudes, two reflections, one self-affirmation.

Foldable input modules sit under each header. Focusing an input triggers a sun animation, giving writing a warm, ritual feel.

When done, AI generates a unique illustration from the day's content as a mark for the day.

(2)Calendar

Two modules. Top: a monthly calendar—completed days show a thumbnail of the AI illustration; tap to open the full 3-2-1 record.

Bottom: the Scratch module. The system gathers all past Gratitude entries, sends them to an LLM for semantic integration, and hides a refined positive line under the overlay. Scratch to reveal a memory from the past.
